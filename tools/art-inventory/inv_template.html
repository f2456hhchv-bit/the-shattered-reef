Shattered Reef Art Inventory

Every piece of art in the game, checked against the standard: the simple toy harbour (2026-10-08). Each asset shows how it draws in the game today, its style and how urgently it needs redoing. Nothing stays code-drawn (2026-10-12): panels, buttons, bars, rings, land, water and weather all get drawn art too, and How it's made shows how each kind is drawn and used. The prompt kit is everything you need to brief ChatGPT, in one place. Last full review against the live game: 2026-10-11.

Overview

The standard

A simple chunky toy, like a child's wooden or plastic playset piece. A few big rounded blocks (about 3-6 parts), thick silhouette, slightly squat cute proportions. Three or four flat matte colours, soft light from the top-left, smooth with no texture.

No clutter. No small props (barrels, crates, cannonball piles, ropes, chains, ladders, lanterns), no brick or plank lines, no rivets, scales, cracks, patterns, windows grids or text. If a part wouldn't be visible at 48px, leave it out.

The harbour mockup sets this standard; attach it to every request. The first toy pass (ships, buildings, towers, most creatures) is too detailed: same family, too many parts. Never use the word "painted" in a prompt.

Restyle priority, in order

  1. Creatures and bosses (G, A), in progress: 9 creatures (G1-G9) and all 12 bosses left. Every prompt spells out exactly what the creature looks like from its view.
  2. UI kit (K): the panels, cards, buttons, chips, tabs, bars, pips and dock tiles that every screen and the HUD are built from. Start with K1 (panel) and K9 (gold button); once they're right, attach them to every later kit chat so the set stays one family.
  3. Terrain surfaces (L): land, shore and water fill most of the screen in play. Tropical first (L1-L3): I add texture sampling to the terrain renderer when they arrive, then the other nine biomes and the harbour follow.
  4. Island outlines (O2) and icons (D, E): 30 islands that aren't round; the missing icons, including the arrows and pause bars the UI still writes as text; then the stand-ins.
  5. What you read in a fight: markers and rings (M), shots (X, X2) and weather particles (Q).
  6. Props (P), towers (T), landmarks (F), title and crests (U).
  7. Low: straight-body redraws (N, needed before the animation build), weather objects (W), Reef Defence extras (R).
  8. Done: chart islands (I), pads and rock islets (O), harbour buildings (B), player ships (S; enemy ships follow), pickups (C) and effect animations (H).

Animation (the last build stage)

  • Everything should end up feeling alive. The plan is to animate in code from one still image per creature, so the art has to be drawn in a pose code can move.
  • Flyers (gulls, bats, wisps' flames, the flying wyrm): wings spread flat at their widest. Code squashes them in and out to flap. If that looks thin, a second "wings down" image per flyer is the fallback.
  • Long bodies (serpents, eels, leeches, worms, tentacles): drawn dead straight. Code bends the image along a moving wave to wriggle it. A curved drawing can't be straightened, which is why batch N redraws the current curved ones.
  • Swimmers and walkers (sharks, crabs, golems): a symmetrical neutral pose. Code adds the sway, bob and squash.
  • UI: buttons swap to their PRESSED image, bars fill, pips light up, rings sweep round. Code swaps and crops the art; it doesn't draw any of it.

Do

  • Attach the harbour mockup to every request. When redoing an asset, attach its current image too; for kit pieces, attach the first finished piece of the kit. The style follows the pictures far more than the words.
  • Ask for one asset per message, on a transparent background (flat #FF00FF magenta if it can't).
  • Every item names its format in brackets: TOP-DOWN for things that swim or fly, FRONT for upright things, FLAT for UI pieces, and so on. How it's made shows each one and why the game needs it.
  • Ships only: one image with 5 views in a row (see the prompt kit).
  • Name each image by its code (e.g. "K9") when you send it, so it lands in the right slot.
  • Fill most of the frame; around 1024px is fine. The game trims and scales it.

Don't

  • Don't accept busy results: small props, plank or brick lines, ropes, chains, many windows. Reply with the fix line below rather than starting again.
  • Don't accept painterly or textured results either.
  • Don't let it put words, numbers or icons on UI pieces. The game writes them on top.
  • Don't accept an ornament in the middle of a 9-SLICE or 3-SLICE edge. That part gets stretched, so it smears.
  • Don't accept a SEAMLESS surface with a shape or a border (an island, a patch, a framed square). It must fill the square and repeat; the map supplies the coastline.
  • Don't send 24-frame turn sheets, 8-direction pre-rotations, or re-renders of the game's current art. None of them worked last time.
  • Don't bake in shadows, water, glows or text. The game draws its own. A clean edge keys out better than a halo.
  • Don't accept a painted grey checkerboard as the background. It isn't transparency, and it eats pale grey and white parts when it's keyed out.
  • Don't copy the last image in a creature or island batch. If it hands back the same outline or pose, reply with the fix line below.

When ChatGPT drifts

  • It holds the style for 3-4 images, then slips. Start a fresh chat every batch, or every 3-4 images.
  • If it writes code or describes the image instead of making it, start a fresh chat. Arguing doesn't fix it.
  • Too busy? Reply: Too many parts. Half as many pieces, no small props, bigger simpler shapes. Same subject and view.
  • Too detailed or textured? Reply: Simpler, like the attached harbour. Chunky blocks, flat matte colours, no texture or lines. Same pose.
  • Wrong view (side or three-quarter instead of from above)? Reply: Wrong view. Camera directly overhead looking straight down: I should see its back, head at the top of the image, body straight and symmetrical.
  • Same as the last one? Reply: Too close to the previous image. New outline and pose, same style.
  • Kit pieces drifting apart? Reply: Same family as the attached piece: same outline, lip, corners and colours.
  • A surface with an edge or a shape? Reply: No shape and no border. Fill the whole square edge to edge so it repeats with no visible join.
  • The header makes it restate the asset, format and style before each image. If that line is missing or wrong, the image will be too.

How it's made

Every visible surface in the game is now meant to be drawn art: creatures, panels, buttons, bars, rings, land, water, rain. Code's only job is to place, stretch, crop, tint, turn, fade and animate that art, and to write the words. Each item in the prompt kit names its format in brackets, like (9-SLICE), and each batch's Copy button gives ChatGPT the definitions for just the formats in that batch.

What ChatGPT can't do exactly, and what I fix on arrival

  • It only draws on three canvas shapes (square, 3:2 wide, 2:3 tall), so long pieces like bars and buttons come back centred on a bigger canvas. I trim them.
  • Frame edges that must be plain, and surfaces that must repeat, come back close but not exact. I straighten the edges and run a tiling pass, then check each one repeated side by side.
  • A kit drifts after 3-4 images. Once the first piece is right (K1 panel, K9 button), attach it to every later kit chat with the harbour image.
